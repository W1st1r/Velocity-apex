# Velocity Apex — Free Roam Network V24

## Серверы
- Свободный режим переведён с 6 серверов по 20 игроков на **3 основных сервера по 50 игроков**:
  - APEX CITY 01 — 50
  - APEX CITY 02 — 50
  - APEX CITY 03 — 50
- Owner Panel и серверный мониторинг также работают только с этими тремя основными серверами.

## Оптимизация сети
- Частота обычных state-пакетов снижена и стала адаптивной к RTT/очереди WebSocket.
- Drag сохраняет отдельную повышенную частоту для точного серверного финиша.
- Добавлен AOI/state fan-out:
  - ближайшие игроки получают частые координаты;
  - дальние игроки получают более редкий pulse;
  - игроки одной активности всегда получают приоритетные обновления.
- Дальние машины не нагружают основной canvas: полноценный рендер машин выполняется только в видимой области камеры.
- Интерполяционный back-time динамически учитывает RTT, что уменьшает рывки при нестабильном соединении.
- Экстраполяция ограничена, чтобы машина не продолжала далеко «лететь» после потери пакетов.
- Добавлен контроль `WebSocket.bufferedAmount`, чтобы не накапливать очередь старых координат при плохом интернете.
- Полный roster больше не рассылается каждые 2 секунды без необходимости; периодическая синхронизация снижена до 10 секунд, а join/leave/timeout всё равно рассылаются немедленно.

## Стабильность соединения
- Клиент автоматически переподключается после краткого сетевого разрыва (несколько быстрых попыток с backoff).
- Для Free Roam используется короткий reconnect grace 5 секунд, без отображения «призрачной» машины другим игрокам.
- Heartbeat Free Roam ускорен: timeout 6.5 секунд, sweep 2 секунды.
- При WebSocket close игрок **сразу исчезает из публичного списка и с карты**, даже если его сессия кратко хранится для reconnect.
- При штатном выходе игрок удаляется сразу.
- При закрытии страницы/PWA добавлен HTTP `leave` beacon как резерв к WebSocket `leave`.
- При возврате из browser bfcache клиент не остаётся в сломанном старом состоянии.

Эти изменения уменьшают серверную и клиентскую нагрузку и снижают сетевые микрофризы. Фактический ping в миллисекундах всё равно зависит от маршрута пользователя до Cloudflare/расположения Durable Object и качества его сети.
