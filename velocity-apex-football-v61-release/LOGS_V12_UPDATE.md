# APEX — OWNER LOGS V12

Добавлен отдельный серверный раздел **OWNER PANEL → LOGS / ЛОГИ**.

## Что реализовано

- Единая серверная таблица `game_logs` с уникальными ID вида `LOG-XXXXXXXXXXXX`.
- Категории: блокировки, муты, входы/выходы, покупки, продажи, система, чат.
- OWNER-only API `/api/owner/logs`.
- Глобальный поиск по игроку, ID, администратору, тексту, причине, сделке и серверу.
- Фильтры по периоду, серверу, роли автора и типу события.
- Cursor/lazy pagination по 50 записей.
- Автообновление открытого журнала раз в 15 секунд.
- Подробная карточка лога.
- Полностью отдельный экран Logs в OWNER PANEL с адаптацией под телефон/iPhone.

## Что логируется на сервере

- BAN / UNBAN и MUTE / UNMUTE через существующую систему администрирования.
- Вход и выход из свободного/онлайн режима, длительность сессии и причина отключения.
- Сообщения игрового чата со всех свободных серверов, с сервером, игроком и префиксом.
- Покупки магазина/гаража/тюнинга/кейсов по подтверждённому сервером изменению cloud-save.
- Покупки, продажи и заявки рынка непосредственно во время серверной транзакции.
- Выдачи валюты, ресурсов, машин, LEVEL и другие действия OWNER/ADMIN через audit.
- Награды прогрессии и live events.
- Промокоды.
- Реферальные награды.
- Еженедельные выплаты кланов.

Клиенту не предоставлен API создания, редактирования или удаления логов. Критические записи формируются сервером.

## База данных

Добавлена миграция:

`migrations/0012_game_logs.sql`

Worker также вызывает `CREATE TABLE IF NOT EXISTS`, поэтому таблица безопасно создаётся при первом обращении к системе логов даже до ручного применения миграции.

## Проверка

Добавлен тест:

`tests/logs_system_test.mjs`

Он проверяет OWNER-only доступ, поиск/фильтры, уникальный Log ID, покупочные diff-записи и наличие интерфейса Logs.

Полный `npm test` проходит вместе со всеми существующими тестами проекта.

## Обновление

```bash
npm test
npx wrangler d1 migrations apply velocity-apex-db --remote
npx wrangler deploy
```

Если миграция уже была создана автоматически Worker-ом, команда migrations apply остаётся безопасной из-за `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`.
