**CONDITIONAL — технический аудит.** Четыре подтверждённых дефекта исправлены; итоговая автоматизация зелёная. **Общая локальная приёмка остаётся BLOCKED**, как в `V2_RELEASE_READINESS.md`: обязательный визуальный прогон из предыдущего этапа не выполнен. ## B. Конкретные исправления

### AUDIT-01 — списание взноса без зачисления, P0

- **Файл/функция:** `src/crews.mjs`, `handleCrewRequest`, POST `/api/crews/treasury/contribute`.
- **Причина:** между debit игрока и вставкой ledger стоял `INSERT OR IGNORE crew_treasuries`. Для существующей казны он давал `changes()=0`, стирая признак успешного debit.
- **Проявление:** первый взнос проходил; второй с новым idempotency key списывал CR игрока, не записывал перевод и возвращал 409. Новый тест на старом коде получил 409 вместо 200.
- **Изменение:** создание пустой казны перенесено перед debit в той же D1 batch; ledger непосредственно проверяет изменения debit, а treasury credit — изменения ledger. Повторные ключи по-прежнему не списывают деньги.
- **Доказательство:** `tests/crews_reports_test.mjs`: второй взнос, сумма 27 000 CR после трёх подтверждённых операций; искусственная ошибка ledger откатывает debit и казну, затем retry проходит один раз.
- **Соседи:** вместимость/стоимость мест, REP, weekly payout, права и report API проверены тем же тестом; общий economy/regression набор также прошёл.

### AUDIT-02 — пересекающиеся выплаты и неатомарный cursor, P0

- **Файл/функции:** `src/clan-district-income.mjs`, `postInterval`, `settleClanDistrictIncome`.
- **Причина:** ключ включал оба конца интервала, но cursor записывался отдельным безусловным UPDATE после платёжной транзакции. Два читателя одного cursor с разными `now` получали разные ключи и оба оплачивали общий участок; stale writer мог откатить cursor.
- **Проявление:** два параллельных cutoffs 24/48 ч для района 3 000 CR/сутки давали 9 000 вместо 6 000 CR. Ошибка воспроизведена на SQLite до патча.
- **Изменение:** cursor CAS, оба журнала и баланс теперь входят в одну batch. Guard сравнивает cursor, income owner, фактического owner и capture timestamp. Stale snapshot не оплачивается и не переписывает более новое состояние. Повтор ограничен шестью попытками; при более долгой конкуренции остаток безопасно подхватывается следующим запуском. Инициализация NULL cursor теперь явная, без `Number(null)`.
- **Доказательство:** `tests/clan_district_income_v2_test.mjs`: 6 000 CR при разных параллельных cutoffs, cursor на максимальном cutoff; write fault откатывает cursor/journals; lost ACK оставляет cursor и credit committed, retry не платит повторно.
- **Соседи:** прежние same-time concurrency, handoff между двумя кланами, rates, last24h, повтор миграции и D1 release прошли. SQL-схема и координаты районов не менялись.

### AUDIT-03 — потеря дробного дохода при частых расчётах, P1

- **Файл/функция:** `src/clan-district-income.mjs`, `prorated`.
- **Причина:** округлялся каждый короткий интервал, после чего cursor навсегда отбрасывал его остаток.
- **Проявление:** двенадцать запусков по 10 с приносили 0 CR, хотя те же 120 с одним запуском приносили 4 CR для обычного района.
- **Изменение:** выплата — разность накопленных целочисленных значений на границах времени, вычисленная через BigInt. Дробные остатки времени сохраняются между вызовами; суточные ставки не изменены. Перенос целочисленного CR возможен менее чем на 1 CR относительно прежнего округления одного интервала; итог больше не зависит от частоты вызовов.
- **Доказательство:** тот же income test сравнивает 12 коротких начислений с накопленным значением; контрольный запуск старой функции отдельно показал 0 против 4.
- **Соседи:** полные/половинные сутки, передача владельца, projectedDaily/last24h, payout replay прошли.

### AUDIT-04 — завершение сезона с необработанной очередью, P1

- **Файл/функции:** `src/clan-seasons.mjs`, `finalizeSeason` и его два вызывающих пути.
- **Причина:** outbox-проход ограничен 20 страницами по 200 строк; после достижения лимита `settleClanCompetition` всё равно финализировал истёкшие сезоны.
- **Проявление:** 4 000 событий перед последним подтверждённым матчем — сезон становился FINISHED до применения матча, поэтому клан терял право участия/награду. Тест до патча получил FINISHED вместо OPEN.
- **Изменение:** перед финализацией проверяется наличие pending событий с timestamp до конца сезона. Пока очередь не обработана, сезон остаётся возобновляемым; оба вызывающих пути не сообщают о нём как о завершённом.
- **Доказательство:** `tests/clan_seasons_v2_test.mjs`: backlog 4 001; первый запуск оставляет OPEN без results; второй учитывает последний матч и награду; повтор не увеличивает баланс.
- **Соседи:** все прежние season/task tests, пять дивизионных выплат, UTC cutover, ranking/shared place и recovery после частичной выплаты прошли.

## C. Оставшиеся риски

Новых подтверждённых открытых P0/P1 после исправлений нет **в объёме выполненных сценариев**. Это не доказательство отсутствия всех возможных дефектов.

- Исторические записи, уже повреждённые старым кодом, автоматически не корректировались. Реальные пользовательские данные не читались. Перед любым будущим выпуском с переносом существующей V2-базы нужна отдельная сверка её журналов и балансов; она не разрешена в этой сессии.
- Прошлые пределы покрытия из QA-матрицы сохраняются: реальный Cloudflare WebSocket/D1/DO цикл, внешние провайдеры и все возможные межпроцессные interleavings здесь не воспроизводились. Тесты проверяют локальную SQLite и имеющиеся fixtures.
- При долговременной конкуренции income CAS может отложить часть начисления до следующего вызова; cursor не теряется и долг не списывается. Нового unlimited retry не добавлено.

## D. Coastal Ridge и ограничения

`public/js/crews.js:districtPanel` выводит `x.name` из D1 с HTML escaping, а не `ApexCity.district(x,y)`. Общий resolver применяется к крупным городским областям, поэтому Industrial Park на этой координате сам по себе не доказывает неверную подпись кланового маркера. Исправление resolver/координат без такого доказательства не вносилось. Pin остаётся (4580,1390); геометрический тест и district-ID capture/income tests проходят. **Визуально не проверено.**

Браузер и CUA по указанию пользователя не запускались; браузеры/библиотеки/новые зависимости не устанавливались. Safari/iPhone не проверен, физическая приёмка остаётся отдельным будущим этапом. Алгоритмы ботов, характеристики автомобилей, коэффициенты экономики и production V77 не менялись. Push, merge, deploy, production migrations/D1/DO и реальные балансы не затрагивались. Старые ZIP не изменялись.

## E. Сохранение и следующий этап

Все исправления, регрессионные тесты и этот отчёт включены в один локальный checkpoint. Его полный SHA указан в итоговом сообщении и `CHECKPOINT.txt` новой резервной копии (самоссылочный SHA внутри коммита невозможен). Bundle содержит всю доступную Git-историю; source archive — tracked исходники без вложенных ZIP. Старые архивы не перезаписываются. Проверки восстановления и SHA-256 выполняются после создания checkpoint; их фактический результат сообщается отдельно.

Следующее наиболее полезное действие: выполнить сохранённый список визуальной приёмки в браузерном окружении с доступом к локальному приложению; до этого общая локальная приёмка остаётся BLOCKED.
