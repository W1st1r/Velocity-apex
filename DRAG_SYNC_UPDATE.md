# Velocity Apex — Free Roam Drag Sync V2

Обновление устраняет ложный визуальный порядок финиша в drag-заездах при сетевой задержке.

## Что изменено

- Победитель drag теперь определяется только сервером по пересечению финишной линии.
- `elapsedMs`, присланный клиентом, больше не влияет на результат.
- Добавлена постоянная NTP-подобная синхронизация времени клиента и сервера.
- Добавлен серверный RTT-probe: сервер независимо оценивает сетевую задержку и ограничивает доверие к клиентскому timestamp.
- Во время drag частота отправки состояния повышается до ~33 Гц; вне drag остаётся ~20 Гц, чтобы не перегружать сервер.
- Удалён старый «догоняющий» tween чужой машины; используется timestamp interpolation + bounded extrapolation по скорости/yawRate.
- Сервер передаёт `activity_progress` с общей серверной оценкой текущего лидера и отрыва.
- Добавлен LIVE HUD: SERVER LIVE, PING, кто впереди, примерный отрыв в корпусах и индикаторы прогресса до финиша.
- Финиши с разницей до 0.100 с помечаются как PHOTO FINISH.
- При выходе/обрыве связи соперника drag корректно отменяется и не зависает.
- Старое клиентское сообщение `activity_finish` оставлено совместимым, но сервер намеренно его игнорирует.

## Проверка

Добавлен `tests/free_drag_sync_test.mjs`: он специально отправляет серверу пакет проигравшего раньше пакета победителя и проверяет, что победитель всё равно определяется по синхронизированному времени пересечения финиша, а не по порядку прихода пакетов.

Полный `npm test` проходит.

## Обновление через GitHub / терминал

Загрузите `Velocity-Apex-Drag-Sync-V2.zip` в корень репозитория и выполните:

```bash
unzip -o Velocity-Apex-Drag-Sync-V2.zip -d .
rm Velocity-Apex-Drag-Sync-V2.zip
npm test
git add .
git commit -m "Fix Free Roam drag synchronization"
git push
```

Если проект разворачивается вручную через Cloudflare Workers после push:

```bash
npx wrangler deploy
```
