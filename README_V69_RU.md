# Velocity Apex V69 — Upgrade Protection & iOS 17+ layout pass

Дата сборки: 14.10.2026. Основа: V68 Controls & UI Polish.

## 1. Upgrade — что изменилось

- Один Upgrade, без отдельных вкладок режимов. **Защита ставки** — опциональный переключатель в правой карточке выбора цели, по умолчанию выключен.
- Шансы **не зависят** от возраста аккаунта, уровня, количества попыток, побед, поражений или времени в игре. Удалены обращения к таблице попыток и прогрессии ради расчёта вероятностей.
- Обычная ставка: `chanceBps = min(9500, floor(stakeValue / targetValue × 9600))`.
- Защищённая ставка: при неудаче после списания предметов и CR возвращается **25% оценочной стоимости всей ставки в CR**. Для одинаковой ожидаемой отдачи вероятность успеха уменьшается: `floor(7100 × stakeValue × 10000 / (10000 × targetValue - 2500 × stakeValue))` (макс. 9500 bps).
- Ожидаемая математическая отдача ~96% до ограничения максимальной вероятности и округлений. **Это не вероятность выигрыша и не гарантия прибыли.**
- Пример: 500 000 CR оценочной ставки при цели 1 000 000 CR: 48% без защиты; 40,57% с защитой. При защищённой неудаче возвращается 125 000 CR на баланс, но **не возвращаются автомобили/эффекты**.
- В серверном ответе Quote, Attempt и истории сохраняется состояние защиты, рассчитанный возврат и итоговый зачисленный возврат. Повтор того же `upgradeId` не повторяет списание и начисление.
- Шанс, анимация стрелки и зелёный сектор совпадают; алгоритм самих пограничных остановок V65 сохранён.
- Подтверждение предупреждает, если риск затрагивает 40% или больше оценочного имущества.
- Если полное начисление возврата превышает лимит CR, сервер отклоняет защищённую ставку **до** списания, вместо частичного начисления.
- Старые попытки и история сохранены, новое поведение применяется только к новым прокруткам. Изменения структуры D1 не требуются.

## 2. Интерфейс iOS 17+ / iPadOS

- Добавлен отдельный CSS `public/css/ios-upgrade-v69.css`, подключён **после** всех старых стилей.
- Вкладки, окна и карточки получили ограничения по фактической высоте экрана `100dvh`, учёт iOS safe-area и прокрутку внутри модальных окон.
- Ограничены ширины полей и карточек, улучшена обработка длинных текстов, введены подходящие размеры формы для предотвращения автозума Safari при вводе.
- Защита ставки помещена рядом с выбором цели и читается даже в компактном ландшафтном интерфейсе.
- Сохранены управление, расположение кнопок, цвета результатов Upgrade, гараж, карьера, онлайн, магазин, кланы, сохранения игроков.
- Портретный режим смартфона по-прежнему показывает предусмотренное игрой приглашение повернуть телефон; гонки остаются горизонтальными.

## 3. Подтверждённые тесты

- `npm test` — штатный набор проекта пройден.
- `npm run test:v69` — серверная формула, серверная интеграция с SQLite, idempotency, тесты V68 и V67 пройдены.
- Тестовая SQLite: профили со стажем и без получают одинаковые шансы; защищённый проигрыш, повтор попытки без двойного начисления, успех, история, занятые цели — пройдены.
- Проверены значения вероятностей для 2%–99% от стоимости цели на трёх ценовых диапазонах, округление и возвращаемые CR.
- Аудит размеров в Chromium с мобильной эмуляцией: **15 разрешений** (iPhone compact, стандартные/Plus/Pro Max, iPad mini/Air/Pro; ландшафт и портрет) × **20 крупных окон** = 300 проверок. 249 видимых экранов без выхода за экран/горизонтального переполнения; 51 скрыто согласно состоянию/ориентации. Дополнительная ручная проверка сетки Upgrade на 14 разрешениях.
- Проверен синтаксис JS и структура HTML без дублирующихся ID.

## 4. Границы проверки

- Chromium mobile emulation **не равно** настоящему iOS Safari/WebKit. Физически все модели iPhone и iPad не были доступны. Реальные жесты, аппаратные вырезы, экранную клавиатуру, производительность PWA, звук, спящий режим и переключение приложений нужно перепроверить после деплоя.
- В автоматических тестах охвачены существующие игровые режимы и API, но нельзя доказать отсутствие абсолютно всех багов или проверить произвольное число реальных игроков одновременно.
- Реальные платёжные операции и Cloudflare на рабочем домене из этой сборочной среды не выполнялись. ZIP и скрипт предназначены для публикации пользователем.

## 5. Порядок деплоя

1. Загрузить `Velocity-Apex-Upgrade-Protection-iOS-V69.zip` и `Velocity-Apex-V69-One-Paste-Deploy.sh` в ветку `main` через https://github.com/W1st1r/Velocity-apex/upload/main и нажать `Commit changes`.
2. В терминале GitHub Codespaces выполнить:
   `cd /workspaces/Velocity-apex && git fetch origin main && git show origin/main:Velocity-Apex-V69-One-Paste-Deploy.sh | bash`
3. Скрипт проверит SHA256 и ZIP, развернёт в чистую worktree, запустит тесты, отправит исходники в GitHub, затем выполнит прямой `wrangler deploy` и проверит `https://velocity-apex.maximmanzha20.workers.dev/version.json` плюс CSS V69.
4. По результатам на настоящем iPhone проверить Upgrade с и без защиты на малых ставках, отображение возврата в истории, взаимодействие с клавиатурой, онлайн и повторный запуск PWA.

**Не загружать ZIP в окно редактора как текст:** загружать оба файла через обычную страницу GitHub. База D1 и пользовательские записи не удаляются.
